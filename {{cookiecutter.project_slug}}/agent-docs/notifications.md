# 消息通知开发规范

## 接入边界

- 业务模块必须调用 `apps.notifications_center.services.send_notification`，不得直接
  调用 `notifications.signals.notify.send` 或写入第三方通知模型。
- 发起者、业务对象和目标对象必须是已保存的 Django 模型实例。
- 收件人可以是单个用户或用户集合；服务负责去重，空集合视为无需发送。
- 标题、正文和级别承载展示内容；扩展元数据保持 JSON 可序列化。
- 跳转地址只能使用以 `/` 开头且不以 `//` 开头的站内路径，禁止外部 URL。

## 权限与事务

- 前台通知页面和所有状态修改接口必须登录后访问，并始终按 `recipient=request.user`
  限定查询。
- 状态修改只接受 POST，并保留 CSRF 防护；业务链接跳转不得隐式标记已读。
- 后台发布在事务中完成，使用 `published_at` 作为重复发送保护；已发布记录保持只读。
- “全部启用用户”以发布时 `is_active=True` 的查询结果为准。
- 首版同步发送。迁移到 Celery 时必须增加业务幂等键、失败重试和广播批处理。

## 测试要求

- 服务测试覆盖用户去重、空收件人、级别、正文、业务对象和非法跳转路径。
- Admin 测试覆盖两种收件范围、停用用户排除、发布数量和重复保存不重发。
- 前台测试覆盖登录、筛选、分页、读状态、CSRF 和跨用户越权。
- 第三方通知表由第三方 migration 管理；项目发布记录模型同步维护 migration、测试和
  MySQL 8 参考 SQL。
